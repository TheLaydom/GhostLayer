Gemini delivered a React side panel, an independent MV3 entry point, categorized findings, a mock cloud response, distinct local and cloud adapters, and persisted policy settings. No separate Neon Gemini artifact was available for attribution.

- **Release blocker, build.** With the declared Firebase 11.x dependency, both type-check and build failed with TS2305 and TS2561 in `src/services/firebase.ts` at the hybrid mode import and model calls. Firebase 13.4.0 resolved those TypeScript errors in the review copy. Vite 6 then hit an esbuild child-process permission error on this host. The same source built with Vite 8.3.8 and React plugin 6. Pin compatible dependencies, track their lockfile, and review the four high advisories reported under the Firebase dependency tree.
- **Release blocker, local model initialization.** `src/services/firebase.ts:94` constructs the device-only model and calls generation without the explicit `initializeDeviceModel()` that the current Web SDK requires. Initialize during a user gesture and propagate failed initialization to the blocked review. [Firebase hybrid Web setup](https://firebase.google.com/docs/ai-logic/hybrid/web/get-started)
- **Release blocker, scan status.** A fake device runner returning malformed JSON caused `src/services/localAi.ts:229` to report `ready` with zero findings. A valid empty entity list and malformed output need distinct outcomes. The strict gate must block the latter.
- **Release blocker, unchanged fallback request.** The conditions in `src/App.tsx:124` allow a rules-only review with unavailable Nano and no findings to reach the transport as the original text. Require the core's reviewed-text gate and block an unchanged rules-only preview.
- **High, stale approvals.** The input remains editable during `handleScan` in `src/App.tsx:97`. An earlier analysis can resolve after newer input cleared the snapshot. Policy changes at line 92 also retain the snapshot. Invalidate on input or policy revisions and check the active revision immediately before sending and when applying replies.
- **High, placeholder collision.** A source containing `[EMAIL_1]` and one synthetic email produced two `[EMAIL_1]` tokens through `src/core-adapter.ts`. Its round trip replaced both with the email. Use the core's reserved-token handling and current-review mappings.
- **High, App Check credential and enforcement.** `src/services/firebase.ts:73` reads an App Check debug token through a Vite build-time variable, which can embed it in distributed JavaScript. Use a runtime-generated private debug token or a production provider. Acquire and validate App Check before calling live generation. The current no-provider branch still constructs a live adapter.
- **Measurement accuracy.** `src/App.tsx:101–104` includes awaited Nano time in the rule timing. Measure deterministic detection, contextual inference, and network time separately.

The local detector benchmark used Node 26.13.1, four warmup scans, then 25 measured scans per implementation on identical synthetic strings. The 8,000-character plain fixture yielded zero findings for both. Gemini averaged 0.07 ms and Codex 0.11 ms per scan. The 7,840-character fixture yielded 560 findings for both. Gemini averaged 1.07 ms and Codex 0.35 ms per scan. This measures deterministic JavaScript only. It did not measure UI performance, model latency, throughput, or detection accuracy on representative data.

A comparative score is pending integrated behavior, browser evidence, and reciprocal review. The isolated review reproduced two behaviors and audited the build and privacy boundaries. The two agents worked in different lanes, so these timings are scoped to the overlapping detector code.
